# Pattern index

Written by `scripts/validate --write` from `kb/patterns/`. Do not edit by hand.

| No. | Name                                                                                                                                                | Tier             | Classes                                                      | Rule of use                                                                                                                                                                                                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | [Animated toggles (switches)](patterns/01-animated-toggles-switches.md)                                                                             | core             | functional-feedback, comprehension                           | Use a switch only for a binary setting that takes effect immediately. The thumb moves and the colour changes to show the new state, and a visible result must confirm it worked.                                                             |
| 2   | [Selection and like bursts](patterns/02-selection-and-like-bursts.md)                                                                               | rarely-justified | emotional-engagement, decorative, functional-feedback        | Show selection with an instant, labelled state change (fill, colour plus shape, aria-pressed). Add a particle or scale burst only in consumer or social contexts, never on repeated operational selections.                                  |
| 3   | [Loading spinners](patterns/03-loading-spinners.md)                                                                                                 | core             | functional-feedback, perceived-performance                   | Show an indeterminate spinner only for waits of about 1 to 10 seconds with unknown length, placed on the thing that is waiting. Under 1 second, show only a static pending state, no spinner; past 10 seconds, a percent-done indicator.     |
| 4   | [Progress bars](patterns/04-progress-bars.md)                                                                                                       | core             | functional-feedback, perceived-performance, comprehension    | Use a determinate bar with a text count whenever work is measurable or may exceed 10 seconds. Advance it honestly, never backwards, and offer Cancel for long jobs.                                                                          |
| 5   | [Animated checkboxes](patterns/05-animated-checkboxes.md)                                                                                           | core             | functional-feedback, decorative                              | The checked state appears instantly and unmistakably. Animating the check mark is optional decoration, kept under 150 ms, and never delays the state or the next click.                                                                      |
| 6   | [Radio groups](patterns/06-radio-groups.md)                                                                                                         | core             | functional-feedback, error-prevention                        | Use radios for exactly one choice among a few visible options. Show the selection instantly with a filled dot and the arrow-key behaviour, and never use radios to trigger actions or navigation.                                            |
| 7   | [Download indicators](patterns/07-download-indicators.md)                                                                                           | core             | functional-feedback, perceived-performance                   | Let the browser or OS show download progress whenever it can. Build in-app progress only for authenticated or generated files, and report "Downloaded" only once the file exists.                                                            |
| 8   | [Upload indicators](patterns/08-upload-indicators.md)                                                                                               | core             | functional-feedback, error-prevention, perceived-performance | Show per-file determinate progress, then a distinct "processing" state, and mark a file uploaded only after the server confirms it. Never discard the local copy before that.                                                                |
| 9   | [Folder transitions (open and close of containers)](patterns/09-folder-transitions-open-and-close-of-containers.md)                                 | core             | comprehension, functional-feedback, navigation               | Every expandable container shows its open or closed state at once and accessibly. Motion is optional: a short height or opacity reveal anchored to the trigger, never one that blocks the next click.                                        |
| 10  | [Document previews (quick look, peek)](patterns/10-document-previews-quick-look-peek.md)                                                            | situational      | comprehension, error-prevention, navigation                  | Let users confirm an item's content without leaving their place. Grow the preview from its source and dismiss it instantly. Never hide essential content or actions behind hover-only peeks.                                                 |
| 11  | [Dot loaders](patterns/11-dot-loaders.md)                                                                                                           | rarely-justified | decorative, functional-feedback                              | Default to the platform spinner. Use animated dots only for an in-stream "someone or something is typing or thinking" cue in chat or assistant UIs, with text for assistive technology.                                                      |
| 12  | [Skeleton loading states](patterns/12-skeleton-loading-states.md)                                                                                   | situational      | perceived-performance, comprehension                         | Use static, layout-accurate skeletons for first loads of full pages or lists lasting about 1 to 10 seconds. Never use them for quick loads, refetches of visible data, or file and process progress.                                         |
| 13  | [Button submission feedback](patterns/13-button-submission-feedback.md)                                                                             | core             | functional-feedback, error-prevention, perceived-performance | On submit, immediately mark the button pending, block resubmission and keep focus. Announce the real outcome only after the server responds, using text and not only a spinner or check.                                                     |
| 14  | [Menu opening and closing](patterns/14-menu-opening-and-closing.md)                                                                                 | core             | functional-feedback, navigation                              | Open action menus immediately from their trigger with a brief opacity/scale; move focus to the first item; close faster than they opened and return focus to the trigger.                                                                    |
| 15  | [Expandable search](patterns/15-expandable-search.md)                                                                                               | situational      | navigation, functional-feedback                              | Keep search visible by default; expand from an icon only where width is truly scarce, focusing the input in the same tap so typing is never delayed.                                                                                         |
| 16  | [Notification indicators (badges and dots)](patterns/16-notification-indicators-badges-and-dots.md)                                                 | core             | functional-feedback, navigation, comprehension               | Put a badge only on the destination that clears it, for unread or actionable items the user owns. Keep the count true, and never make the badge the only signal.                                                                             |
| 17  | [Star ratings](patterns/17-star-ratings.md)                                                                                                         | situational      | functional-feedback, emotional-engagement                    | Build a rating input as a radio group of labelled stars, with no bounce or sparkle. In operational software, prefer a labelled numeric or word scale unless stars are what users expect.                                                     |
| 18  | [Range sliders](patterns/18-range-sliders.md)                                                                                                       | situational      | functional-feedback, comprehension                           | Use a slider only when an approximate value within a bounded range is good enough. The thumb tracks the pointer exactly, the value is always visible, and a typed or tap alternative exists.                                                 |
| 19  | [Tab transitions](patterns/19-tab-transitions.md)                                                                                                   | core             | navigation, comprehension                                    | Swap tab panels instantly or with a crossfade of 150 ms or less; show the selected tab with two cues; never slide whole panels in dense software.                                                                                            |
| 20  | [Grid and list transitions (layout switching, reflow)](patterns/20-grid-and-list-transitions-layout-switching-reflow.md)                            | situational      | comprehension, navigation, decorative                        | Animate reflow only so people can follow where items went after a sort, view switch or insert. Keep it short and transform-only, and skip it for large sets.                                                                                 |
| 21  | [Touch and ripple feedback](patterns/21-touch-and-ripple-feedback.md)                                                                               | core             | functional-feedback                                          | Every pressable gives a visible pressed state within one frame of touch-down and activates on release. Use the platform form: ripple on Android, highlight or opacity on iOS, state layer on web.                                            |
| 22  | [Accordions](patterns/22-accordions.md)                                                                                                             | core             | comprehension, navigation                                    | Use native details/summary or the APG accordion. Animate height only briefly, as an enhancement. Allow several sections open, and never auto-collapse sections users compare.                                                                |
| 23  | [Modal transitions (dialogs, sheets, side panels)](patterns/23-modal-transitions-dialogs-sheets-side-panels.md)                                     | core             | navigation, error-prevention, comprehension                  | Use native dialogs and system sheets with a short fade and a small translate from the edge or trigger. Move focus in, return it on close, and never delay input.                                                                             |
| 24  | [Toast notifications](patterns/24-toast-notifications.md)                                                                                           | core             | functional-feedback, error-prevention                        | Use toasts only for brief, non-critical confirmation of user actions, often with Undo. Never for errors needing action. Announce politely, show at least 5 seconds, pause on hover/focus.                                                    |
| 25  | [Avatar stacks](patterns/25-avatar-stacks.md)                                                                                                       | situational      | comprehension, decorative                                    | Show 2–4 overlapping avatars plus a "+N" count, with a full text list of names for assistive technology. Skip hover-spread and entrance animations in operational software.                                                                  |
| 26  | [Charging and status indicators](patterns/26-charging-and-status-indicators.md)                                                                     | situational      | comprehension, functional-feedback, error-prevention         | Show status as a static text label with an icon and, where useful, a value. Animate only the change between states; never loop a charging fill in operational screens.                                                                       |
| 27  | [Equalizers (audio-level style activity indicators)](patterns/27-equalizers-audio-level-style-activity-indicators.md)                               | rarely-justified | decorative, functional-feedback                              | Use a moving level meter only when it reflects real audio input, such as a mic check while recording. Otherwise an equalizer is decoration: show a static 'Recording' or 'Playing' label.                                                    |
| 28  | [Play and pause transitions](patterns/28-play-and-pause-transitions.md)                                                                             | situational      | functional-feedback, comprehension                           | The play/pause control reflects the actual media state, switching icon and accessible label only when playback really starts or stops, with a brief crossfade at most.                                                                       |
| 29  | [Numeric steppers](patterns/29-numeric-steppers.md)                                                                                                 | situational      | functional-feedback, error-prevention                        | Use −/+ buttons for small adjustments of a value that stays visible and typeable. Update the number instantly, mark the buttons unavailable at the bounds with `aria-disabled`, and never make a stepper the only way to enter large values. |
| 30  | [Progress rings](patterns/30-progress-rings.md)                                                                                                     | situational      | functional-feedback, comprehension                           | Use a determinate circular ring only where space is compact, such as a per-row transfer or a step count in a card. Use a bar where width allows, and always pair the ring with text.                                                         |
| 31  | [Card flips](patterns/31-card-flips.md)                                                                                                             | rarely-justified | decorative, comprehension                                    | Leave card flips out of operational software and use a disclosure, tabs or a side-by-side layout. Flip only when the front-and-back metaphor is the content itself, as in flashcards.                                                        |
| 32  | [Drag-to-sort interactions](patterns/32-drag-to-sort-interactions.md)                                                                               | core             | functional-feedback, comprehension, error-prevention         | Manual ordering must work without dragging: offer move up/down or "Move to…" controls and keyboard moves, and give drag lift, gap and drop feedback.                                                                                         |
| 33  | [Swipe actions](patterns/33-swipe-actions.md)                                                                                                       | situational      | functional-feedback, error-prevention                        | Swipe is only a shortcut on native touch lists: one consistent action per direction, always duplicated by visible or menu controls, with undo for destructive results.                                                                       |
| 34  | [Typing indicators](patterns/34-typing-indicators.md)                                                                                               | situational      | comprehension, emotional-engagement                          | Show 'Name is typing…' only in live person-to-person chat, in a fixed slot by the composer. Expire it automatically and announce it politely at most once per episode.                                                                       |
| 35  | [Floating form labels](patterns/35-floating-form-labels.md)                                                                                         | rarely-justified | comprehension, decorative                                    | Default to static labels above fields. Floating labels only save space and add risks (small text, low contrast, mistaken prefilled values); use them only when a design system requires it.                                                  |
| 36  | [Carousels](patterns/36-carousels.md)                                                                                                               | situational      | navigation, comprehension, decorative                        | Use a carousel only to browse a small homogeneous set such as attached photos. Never auto-rotate in operational software, always pair swiping with visible previous and next buttons, and show a position count.                             |
| 37  | [Connection indicators](patterns/37-connection-indicators.md)                                                                                       | core             | functional-feedback, error-prevention                        | When losing connectivity changes what the user can do, show a persistent, non-blocking banner that states the consequence. Announce it once, and never base it on navigator.onLine alone.                                                    |
| 38  | [Lock and unlock transitions](patterns/38-lock-and-unlock-transitions.md)                                                                           | situational      | functional-feedback, error-prevention, comprehension         | Locking or unlocking a record or control shows the new state in label, icon and the affected UI (editable or read-only) at once. A shackle animation is optional and secondary.                                                              |
| 39  | [Deletion animations](patterns/39-deletion-animations.md)                                                                                           | core             | functional-feedback, comprehension                           | Removing an item must show what went where: a brief fade and collapse for single items, instant removal for bulk, then focus to a sensible neighbour plus a status message with undo.                                                        |
| 40  | [Clipboard confirmation](patterns/40-clipboard-confirmation.md)                                                                                     | core             | functional-feedback                                          | After a copy succeeds, confirm in place (icon and label swap to "Copied") plus one polite announcement. On Android 13+ native, rely on the system confirmation instead of adding a toast.                                                    |
| 41  | [Light and dark mode transitions](patterns/41-light-and-dark-mode-transitions.md)                                                                   | rarely-justified | decorative, emotional-engagement, functional-feedback        | Follow the system appearance and switch themes instantly, with no flash of the wrong theme. An animated theme transition is decoration; suppress all transitions during the swap.                                                            |
| 42  | [Animated data visualizations](patterns/42-animated-data-visualizations.md)                                                                         | rarely-justified | comprehension, decorative                                    | Do not animate charts on load. Animate only a data change the user caused, briefly, and always state the change in text as well.                                                                                                             |
| 43  | [Optimistic updates and rollback feedback](patterns/43-optimistic-updates-and-rollback-feedback.md)                                                 | core             | perceived-performance, functional-feedback, error-prevention | Apply predictable, low-risk changes instantly with a subtle pending marker. On failure, restore the prior state in place, say why, offer Retry, and never fake confirmation of financial, legal or irreversible actions.                     |
| 44  | [Inline form validation](patterns/44-inline-form-validation.md)                                                                                     | core             | error-prevention, functional-feedback                        | Validate a field only after the user finishes it or submits, clear the error as soon as it is fixed, show text plus an icon next to the field, and summarise errors on submit.                                                               |
| 45  | [Undo interactions](patterns/45-undo-interactions.md)                                                                                               | core             | error-prevention, functional-feedback                        | Prefer undo over confirmation for routine reversible actions. Name what will be undone, keep the window long enough and reachable without the toast, and make undo truly reverse server state.                                               |
| 46  | [Command palettes](patterns/46-command-palettes.md)                                                                                                 | situational      | navigation, functional-feedback                              | Add a keyboard-first, filterable command list for heavy desktop users. It opens instantly with the input focused and supplements visible navigation; it never holds the only path to a command.                                              |
| 47  | [Shared-element transitions](patterns/47-shared-element-transitions.md)                                                                             | situational      | comprehension, navigation, decorative                        | Morph an element into its destination only when the same object persists across views and navigation is occasional. Skip it for rapid record-to-record work, and never let it block input.                                                   |
| 48  | [Expandable data tables (row expansion, detail panels)](patterns/48-expandable-data-tables-row-expansion-detail-panels.md)                          | core             | comprehension, navigation                                    | Use a real button with `aria-expanded` to reveal row details without losing table context. Open instantly or with a brief fade, never a slow height animation, and prefer a side panel for deep detail.                                      |
| 49  | [Contextual action menus](patterns/49-contextual-action-menus.md)                                                                                   | situational      | navigation, error-prevention                                 | Treat context menus as accelerators: mirror every action in a visible control, keep them short, mark destructive items, and open at the pointer without delay.                                                                               |
| 50  | [Offline synchronization (queued, syncing, synced, failed)](patterns/50-offline-synchronization-queued-syncing-synced-failed.md)                    | core             | functional-feedback, error-prevention, comprehension         | Give every locally saved change a visible state (saved on device, sending, sent, failed) and show one global summary. Failures stay until resolved, and no change is ever dropped silently.                                                  |
| 51  | [Pull-to-refresh](patterns/51-pull-to-refresh.md)                                                                                                   | situational      | functional-feedback, perceived-performance                   | Use the platform's native pull-to-refresh on mobile lists that do not update themselves, and always pair it with a visible Refresh control. On desktop web, use a button only.                                                               |
| 52  | [Gesture-driven navigation (swipe back, drag to dismiss)](patterns/52-gesture-driven-navigation-swipe-back-drag-to-dismiss.md)                      | core             | navigation, functional-feedback, error-prevention            | Keep the platform's own back gestures and let interactive dismissals track the finger. Always provide a visible Back or Close button, and never let a swipe silently discard unsaved work.                                                   |
| 53  | [Animated numerical counters](patterns/53-animated-numerical-counters.md)                                                                           | rarely-justified | decorative, comprehension, emotional-engagement              | In operational software, show the final value of a number immediately. At most, use a brief digit transition when a watched value changes, and never count up from zero on load.                                                             |
| 54  | [Search filtering transitions](patterns/54-search-filtering-transitions.md)                                                                         | core             | functional-feedback, perceived-performance, comprehension    | Show at once that results are updating and when they are done: dim stale results, update a polite count, keep scroll and focus. Item-level animation is optional and never delays results.                                                   |
| 55  | [Error recovery interactions (retry, resume, restore)](patterns/55-error-recovery-interactions-retry-resume-restore.md)                             | core             | functional-feedback, error-prevention                        | When an action fails, keep the user's input and say in place what failed and why. Offer the single most useful next step (Retry, Resume, Restore draft, Undo) without losing context.                                                        |
| 56  | [Contextual haptic feedback](patterns/56-contextual-haptic-feedback.md)                                                                             | situational      | functional-feedback, error-prevention                        | Use system haptic types for their documented meaning, synced with a visible change. Reserve notification haptics for confirmed outcomes, never as the only channel, and let users turn haptics off.                                          |
| 57  | [Keyboard-driven interactions (shortcuts, roving focus, type-ahead)](patterns/57-keyboard-driven-interactions-shortcuts-roving-focus-type-ahead.md) | core             | navigation, functional-feedback                              | Give each composite widget one tab stop with arrow-key roving focus and type-ahead. Global shortcuts supplement visible controls; single-key shortcuts must be remappable, switchable off, or focus-scoped.                                  |
